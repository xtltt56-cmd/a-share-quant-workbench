# A股量化交易系统可靠性升级交接报告

日期：2026-08-13  
分支：`codex/reliability-upgrade`  
范围：免费数据链路、日选、盘中监控、持仓指导、价格指导、研究训练与运行交付。

## 1. 结论

本轮完成了影响真实使用的高优先级可靠性升级。系统仍定位为“纸面监控与人工决策支持”，不会自动向券商报单，也不承诺收益或预测准确率。没有满足数据质量、交易日历或历史样本要求时，系统会显示不可用/过期，而不会伪造推荐。

## 2. 已修复

- 实时行情优先复用带交易所时间戳的全市场快照，避免单股降级接口污染优先股票。
- 全量快照采用替换语义，上一轮已消失的股票不会继续留在盘中监控中。
- 单只过期行情不再把全部股票统一判为失败；健康接口拆分进程就绪和数据就绪。
- AKShare 超时任务受单工作线程约束，后台关闭时释放调度器和行情提供器资源。
- BaoStock 日线统一为不复权口径 `baostock-unadjusted-v1`；发现旧口径、短历史或损坏文件时自动重建并保留损坏证据。
- 日选最低历史长度固定为 252 个交易日，并使用历史时点证券快照过滤 ST、退市风险和停牌股票。
- BaoStock 额外读取当日可交易清单确定停牌状态，不依赖缺失该字段的基础证券表。
- 使用交易所公布的 2026 年休市安排计算下一交易日；未知年份失败关闭，必须更新日历后才生成指导。
- 持仓指导覆盖“仅从券商导入、未手工登记”的持仓；只有经过质量门的当前价格可进入指导计算。
- 收盘协调器统一刷新日线、官方日选和价格指导，再发布到页面；临时失败保留旧产物并允许重试。
- 官方日选拒绝用更旧的产物覆盖较新的持久化结果。
- 模型治理注册表持久化冠军、评估报告和审批/回滚审计，并用 SHA-256 检测篡改；确认令牌仍是一次性的，且不会落盘。
- 逻辑回归挑战者保存为可移植、可校验 JSON 模型产物，可重新加载复验；所有挑战者仍为 `RESEARCH_ONLY`，不得自动晋升。
- 工作台启动时启动受白名单约束的研究子进程，关闭工作台时保存检查点并停止其拥有的子进程；不设置开机自启动。
- 增加 Python 3.12 直接依赖约束和 Windows GitHub Actions 测试工作流。

## 5. 仍需人工或外部条件

1. 财信普通客户端不是 QMT。若要官方只读行情/资产/持仓接口，仍需财信审批迅投 QMT 与 XtQuant Python 权限，然后安装 QMT；系统当前保留只读接入边界，绝不暴露程序化报单。
2. 免费实时源受网络、限流和交易所时间戳质量影响。系统采用新浪优先、东财/腾讯降级与本地缓存；降级/缓存数据不得显示为 READY。
3. 内置官方休市日只覆盖交易所已经发布的 2026 年。进入 2027 年前必须根据交易所公告更新 `market/trading_calendar.py`，否则指导日期会明确不可用。
4. 挑战者需要至少 60 个交易日影子观察、1000 个成熟样本、多个样本外窗口以及人工审批。收集数据可改善估计和验证，但不能保证推荐更准或盈利。
5. 现有 Qlib 上游代码在 pandas 2.x 下有一条 FutureWarning，当前不影响测试；后续升级 pandas/Qlib 时需复验。

## 6. 日常使用与恢复

- 双击桌面“A股量化交易系统”；启动脚本会打开工作台和本地人工投顾两个页面。
- 首次或历史口径迁移时，免费日线回填可能耗时；不要在写入中强制结束进程。
- 页面先看“进程就绪/数据就绪”和数据年龄；只有质量为良好且未过期的行情才可用于盘中指导。
- 系统异常时先运行 `scripts/stop_quant_workbench.ps1`，再重新双击快捷方式；不要直接删除 `.runtime` 或 `data`。
- 数据恢复使用系统的校验备份/恢复功能；不要手工拼接账本、信号或价格指导 JSON。

## 7. 版本与后续维护

依赖基线位于 `constraints/runtime-py312.txt`。升级依赖时应在新分支运行全量测试、静态检查、真实启动和数据质量验收，再更新约束文件。模型候选的自动训练与评估可以继续演进，但冠军切换必须始终经过成熟门槛、人工确认和可回滚审计。
