# 前瞻模型竞赛与 D 盘存储隔离设计

日期：2026-08-14  
状态：待用户书面复核  
适用项目：`D:\量化交易`

## 1. 目标与不可突破的边界

本升级使用多年历史数据完成训练、特征构建、接口/成本/泄漏排错，以及排除无法运行或明显错误的模型；这些结果只属于工程筛查，不形成冠军、挑战者优胜、临时资格或晋升结论。模型比较与晋升的唯一证据，是参赛版本和评估规则冻结后真正发生的未来行情（prospective out-of-sample）。任何模型都不得自行晋升、下单或改变正式冠军。

所有新增行情、证券池、公司行为、模型、缓存、下载中间文件、临时文件和研究报告必须存放在 `D:\量化交易` 内。运行时如解析后的写入路径位于 C 盘或项目目录外，应在创建文件前失败关闭。不得修改用户全局 `TEMP`、`TMP`、pip 或其他软件配置；仅为本系统进程及其研究子进程设置项目内临时与缓存目录。

## 2. 选定方案：历史工程筛查与前瞻竞赛

### 2.1 历史工程筛查层（不可用于晋升）

系统补齐不少于 7 年、目标不少于 1750 个交易日的研究数据。原因是当前走步切分需要 756 日训练、252 日验证、126 日隔离和126 日测试；约 1750 日才能提供多个独立样本外窗口，而不是只得到一次偶然结果。

历史筛选必须同时满足：

- 按当时可见的上市日、退市日和证券状态建立历史时点股票池；退市股票不得从回测中消失。
- 无法确认当日 ST、停牌或可交易状态的记录不得作为可交易样本。
- 未复权价格继续用于页面价格指导和成交模拟；研究收益与标签使用独立的公司行为处理层，绝不覆盖现有未复权数据。
- 特征只能读取信号日及以前的信息；5、10、20 日未来收益只作为标签。
- 使用滚动走步验证为主、带 purge/embargo 的组合验证为辅；所有参数只在训练/验证段选择，最终测试段一次性冻结评估。
- 计入佣金、印花税、滑点、涨跌停、停牌、最小交易单位、T+1、流动性和容量约束。
- 对每次模型/参数搜索记录尝试次数，并可计算 PBO、Deflated Sharpe、历史 Sharpe、校准误差、最大回撤、换手、不同市场状态稳定性和可复现性，但全部明确标记为 `NON_PROMOTIONAL_DIAGNOSTIC`。
- 任一数据泄漏、产物摘要错误、接口/成本模型错误、无法运行或明显逻辑错误均可将候选标为 `ENGINEERING_BLOCKED`；历史成绩好坏不得产生 `PASS`、优胜、临时资格、审批资格或晋升令牌。

历史层只用于训练、特征构建、排错和排除工程上不可用的模型。历史样本不得计入未来成熟交易日或预测数；不得用 PBO、DSR、CPCV、历史 Sharpe 或任何历史回测指标触发 provisional、formal、promotion 或排序参赛模型。

### 2.2 冻结与预注册未来预测账本

工程筛查完成后，先冻结参赛模型版本、参数、配置、训练数据快照、评估窗口、primary metric、所有门槛和 tie-break 顺序，再启动前瞻竞赛。不得在看到任何未来结果后更换主指标、tie-break、阈值或口径；模型版本或参数发生变化即视为新参赛者，未来成熟交易日和预测数从零开始。

每条预测必须在结果未知且预测时点行情质量合格时，以仅追加、原子持久化的方式预注册。记录至少包含：`prediction_id`、`model_id`、`model_version`、`config_hash`、`training_snapshot_hash`、`symbol`、`name`、`prediction_at`、`as_of`、`horizon`、`score`、`probability`、指导价格区间（买入/观察/风控等 bands）和 `evidence_mode=PROSPECTIVE`。预测不得覆盖或删除，失败预测也必须永久保留；任何修订必须创建新模型版本和新预测记录。

### 2.3 到期结算与比较指标

只有 `horizon` 到期且真实行情通过完整性、新鲜度、交易日对齐和公司行为校验，预测才进入 `matured`。缺失、停牌、行情过期或来源冲突不得被伪造成成功或失败，必须延迟结算并记录原因；结算记录保存结果数据版本和哈希，且不得改写原预测。

前瞻比较至少同时报告方向命中率、Brier、ECE、rank IC、扣除佣金/税费/滑点后的净成本收益、最大回撤、换手、覆盖率/拒绝率和分市场状态稳定性。只有预先冻结的 primary metric 决定主比较，并按预先冻结的 tie-break 处理并列；所有必要风险与质量门槛仍须同时满足，禁止看结果后选择更有利的指标。

### 2.4 20 日临时未成熟观察层

累计至少 20 个未来交易日并取得至少 100 个已到期未来预测后，只可显示为“临时未成熟观察”：

- 页面必须明确标记“临时、未成熟、仅供观察”。
- 不替换正式冠军，不影响正式日选排序。
- 不构成优胜、晋升资格或交易信号；不得据此自动下单。
- 若实时校准、回撤、漂移或数据质量失败，标记风险或暂停展示，但失败预测不可删除。

### 2.5 60 日人工审批入口

挑战者累计至少 60 个未来交易日、至少 200 个已到期未来预测，并同时满足全部预注册指标、数据质量、风险和分市场状态门槛后，才允许进入人工审批。PBO、Deflated Sharpe、CPCV 和历史 Sharpe 不参与该判断。达到条件也不自动晋升、不自动替换冠军且不自动下单。

确认令牌必须一次性使用，晋升和回滚写入现有持久化治理审计。系统永远不提供自动晋升入口。

## 3. 数据架构

新增数据均位于项目目录：

- `data/lake/daily_bars/`：现有未复权执行价格，不改变语义。
- `data/lake/research_returns/`：研究专用公司行为处理收益序列。
- `data/lake/instrument_history/`：上市、退市、ST、停牌和可交易状态的历史时点快照。
- `data/lake/corporate_actions/`：分红、送转、拆并股等事件及来源版本。
- `data/manifests/`：每次下载的来源、时间范围、行数、摘要和数据版本。
- `.runtime/cache/`：本系统网络缓存。
- `.runtime/tmp/`：原子写入、解压和模型训练临时文件。
- `.runtime/research/models/`：挑战者模型与特征模式。
- `.runtime/research/evidence/`：历史工程诊断、冻结竞赛规则、仅追加预测账本和带结果数据哈希的结算证据。
- `reports/research/`：简体中文研究与成熟度报告。

免费数据源按明确接口接入。BaoStock承担长期日线和证券基础信息；AKShare只作为补充与交叉核验。不同来源不得简单拼接，必须先按交易日、证券代码、价格单位、公司行为和版本完成一致性检查。将来接入付费源或 QMT 时实现相同接口，不修改模型和治理边界。

## 4. D 盘强制存储策略

新增 `ProjectStoragePolicy`，启动时固定并解析仓库根目录。所有写入 API 必须通过策略获得目标路径，并执行以下检查：

1. 路径规范化后必须位于 `D:\量化交易`。
2. 拒绝符号链接、目录联接和其他重解析点逃逸。
3. 拒绝设备名、ADS、路径穿越和项目外绝对路径。
4. 下载先写入 `.runtime\tmp` 的同盘临时文件，校验大小、格式和摘要后原子替换目标。
5. 为数据集设置单文件、单次下载和总目录配额；超过配额停止并给出中文原因。
6. 启动研究子进程时，仅在该子进程环境中设置 `TMP`、`TEMP`、`PIP_CACHE_DIR`、`JOBLIB_TEMP_FOLDER` 等为项目内目录；不改系统级环境变量。
7. 下载或训练结束后删除项目内可安全重建的临时文件；正式数据、审计和模型不得自动删除。

启动页增加存储状态：项目根目录、D 盘剩余空间、各数据集占用、最近下载量和是否发生路径拒绝。任何 C 盘写入企图都会进入本地审计，但不记录令牌或完整 URL 查询参数。

## 5. 训练与评估流水线

工作台打开后启动其拥有的低优先级研究子进程：

1. 检查 D 盘空间与数据清单。
2. 增量补齐缺少的日期和历史证券状态。
3. 构建带版本的研究收益、特征和标签快照。
4. 训练逻辑回归基线、LightGBM 候选和可用时的 Qlib 研究模型，并用历史数据做不可晋升的工程筛查。
5. 对所有模型使用完全相同的数据、成本、股票池和评估窗口。
6. 冻结参赛版本、训练快照、primary metric、tie-break 和所有未来门槛，生成竞赛开始记录。
7. 在结果未知前原子追加未来预测；到期且真实行情质量合格后，使用带版本和哈希的结果数据结算。
8. 根据 20/100 与 60/200 未来门槛更新“临时未成熟观察”或“待人工审批”状态，不自动晋升。

关闭工作台时，监督器停止接收新任务，保存完整性校验检查点并停止自己创建的训练子进程。下次打开从已验证检查点继续；损坏或不匹配的检查点保留证据并从最后完整阶段重建。

## 6. 页面与可解释性

简体中文页面新增“模型研究与成熟度”区域，显示：

- 正式冠军、参赛模型版本和比赛开始日。
- 历史数据覆盖率、工程筛查状态，并醒目标注“历史结果不参与晋升”。
- 未来成熟交易日、已到期预测数，以及距离 20/100 临时门槛和 60/200 正式审批门槛的进度。
- “失败预测不可删除”的永久提示，以及当前状态（工程阻塞、竞赛中、临时未成熟观察、待人工审批或已人工决定）。
- 历史诊断与未来竞赛指标分栏，禁止合并成一个夸大的准确率。
- PBO、Deflated Sharpe、Brier、ECE、最大回撤、换手和容量的通俗中文解释。
- 临时指导、正式指导、阻塞和数据不足的醒目标识。
- “为什么不能给出指导”的具体原因，例如历史不足、未来标签尚未到期、行情过期或模型漂移。

系统不显示单一“预测准确率”作为总分，因为分类命中率无法反映收益幅度、交易成本、回撤、拒绝覆盖和概率校准。面向用户的默认摘要使用“未来竞赛 primary metric + 冻结 tie-break + 全部风险门槛 + 当前状态”；历史诊断只用于解释工程质量。

## 7. 故障与安全处理

- 网络失败：保留最后完整数据，标记过期，不以缓存冒充新数据。
- 数据源冲突：隔离冲突股票/日期并生成差异报告，不静默选择更有利的价格。
- 预测到期但行情缺失、停牌或过期：保持未结算，记录延迟原因，不计成功或失败。
- 空数据或短历史：不给模型填充虚构数据，不降低生产门槛。
- 训练失败：保留正式冠军；挑战者记录错误类别和可重试阶段。
- 磁盘空间不足：下载前停止，不写半文件；页面显示所需空间和当前可用空间。
- 工作台关闭：训练和下载子进程停止；已完成的原子产物保留，临时产物下次安全清理。
- 治理状态损坏：失败关闭，禁止晋升，保留文件用于恢复审计。

## 8. 验收标准

- 自动测试证明所有下载、缓存、临时文件、模型和报告均位于 `D:\量化交易`，模拟 C 盘和项目外路径均被拒绝。
- 至少 30 只合格股票达到 7 年研究覆盖；不足者明确排除并展示原因。
- 历史股票池包含已退市样本，且验证日期之后的信息不会进入当日特征或股票池。
- 走步窗口、purge/embargo、成本、涨跌停、停牌、T+1 和容量约束有独立回归测试。
- 同一冻结数据和随机种子重复运行产生相同摘要与核心指标。
- 自动测试证明预测在结果未知前原子追加，字段完整，任何预测（包括失败预测）都不能覆盖或删除，修订会生成新版本。
- 自动测试证明到期但缺失、停牌或过期的数据延迟结算，只有质量合格结果才 matured，且结算保存结果数据版本和哈希。
- 历史结果不能触发任何优胜或晋升状态；20 日/100 matured 只能进入临时未成熟观察；60 日/200 matured 且全部预注册门槛满足后仍必须人工审批。
- 自动测试证明模型版本或参数变化会将该候选的未来计数归零，且看到结果后不能更改 primary metric 或 tie-break。
- 关闭工作台后没有本系统拥有的研究/下载子进程；重启可从完整检查点继续。
- 全量 pytest、Ruff、compileall、pip check、桌面启动和非交易时段失败关闭验收全部通过。

## 9. 明确不在本轮范围

- 自动下单、自动撤单或任何绕过券商审批的接口。
- 承诺收益、保证准确率或以历史结果宣传未来表现。
- 为了缩短周期而用历史结果替代任何未来成熟门槛，或删除 60 日/200 matured 人工审批入口门槛。
- 抓取财信客户端界面、逆向私有协议或模拟人工点击获取行情。
- 修改 Windows 全局缓存、临时目录或其他软件的存储位置。
